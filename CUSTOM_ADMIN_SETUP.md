# Custom admin — deployment checklist

Status: development branch only. Do **not** deploy to production yet.

## Architecture
- Static site generated by `node build.js`.
- Admin page served from `/admin/`, built from `admin/custom.html`.
- Netlify Function: `/.netlify/functions/admin-api`.
- Content source: `content/site.json` in the `main` branch.
- Saving content creates a GitHub commit; Netlify Git integration then rebuilds production.

## Required environment variables (Netlify Functions scope; never commit secrets)
- `ADMIN_USERNAME`: chosen username.
- `ADMIN_PASSWORD_SCRYPT`: `salt:hexhash`, generated using Node crypto.scryptSync with a **random 16+ byte salt** and a strong unique password.
- `SESSION_SECRET`: 32+ unpredictable characters generated by a cryptographic random source.
- `GITHUB_WRITE_TOKEN`: narrowly scoped fine-grained token for this one repository, with **Contents: Read and write** only. Set an expiration and plan rotation.

## Security requirements before launch
- Implement and verify IP/account-based login attempt throttling backed by persistent storage (a memory-only counter in Netlify Functions is insufficient).
- Test CSRF and origin verification, authentication cookie, session expiry and logout.
- Ensure GET requests do not write data; verify concurrency conflict/rollback.
- Validate and normalize WhatsApp numbers, email and text inputs.
- Don't expose admin credentials or GitHub token in client-side files, logs or the public repository.
- Confirm production Netlify automatically builds from the `main` branch.
- Test branch preview and then a single test edit/end-to-end deployment.
- Consider disabling the obsolete Decap admin config after cutover.

## IMPORTANT
The `custom-admin` branch is incomplete and needs a security review and end-to-end test. Do not merge this branch or set credentials yet.
